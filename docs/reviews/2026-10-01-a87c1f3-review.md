## Assessment

**The codebase has improved substantially. Keep it and continue developing it. Most original defects are fixed, and the refactor provides useful boundaries. I do not agree that interruption handling is fully fixed, or that the new storage interface is ready to connect without further work.**

All requested runnable checks passed using the supported alternative Chromium executable. The public benchmark matches the recorded results. I found no unintended counting or WAV regression in the deterministic comparisons described below. These results support preserving the functionality and owner-approved defaults.

The remaining concrete problems concern recovery from one audio-context state, a misleading dark-screen status, interrupted-night sharing, storage isolation, an asynchronous wake-lock race and exported sensitivity-history timestamps. The storage problems affect an unused future interface; they are not evidence that the current app is already corrupting saved nights.

The owner decisions in HANDOVER §2 were respected: Normal remains the default; the 2–12-second rhythm change is approved; background variants remain comparisons; nights stay open through interruptions; persistence/history/accounts remain deferred to 2.x. No counting-policy changes are proposed as automatic fixes.

## 3. Prioritized remaining findings

Priority is relative to this app: **High** means address before relying on unattended iPhone recovery; **Medium** means stabilize before substantial expansion or enabling the affected feature; **Low** means a narrower correctness/lifecycle issue. Simulated evidence is explicitly identified.

### C1 — High: recovery never attempts to resume an audio context whose state is “interrupted”

**Locations:** [recorder:147–150, 162–186][rec-gap]. Every retry checks only `ctx.state === 'suspended'`. The state-change handler recognizes any non-running state as a gap, so an `interrupted` context enters the warning state but receives no resume attempts.

**Executed reproduction:** using the repository’s unchanged fake-browser helper, start recording, set the audio context state, dispatch its state change, run four watchdog ticks and a visible-page event. With `suspended`: **6 resume calls**. With `interrupted`: **0 resume calls**, recorder still interrupted.

**Impact:** the page can say “Trying to resume…” while never requesting it. A browser that requires an explicit resume after this state can leave the rest of the night unrecorded. MDN documents this distinct state and an explicit resume path for iOS Safari; the Web Audio specification also distinguishes it. See [MDN state documentation][mdn-state] and [Web Audio 1.1][web-audio].

**Evidence limit:** the branch omission is verified by execution. Whether a particular iPhone/OS combination automatically recovers despite it was not physically tested. This is not a claim that every iPhone interruption fails.

**Proposed fix/acceptance:** centralize recovery handling for relevant non-running states, distinguishing a permanently closed/ended input. Attempt recovery when appropriate, handle rejected/pending promises, and provide a truthful user action if a gesture is required. Test `interrupted` separately from `suspended`, then verify real call/Siri/foreground transitions on the owner’s phone. Preserve the open-night/gap policy and counting rules.

### C2 — Medium: the dark screen continues to say “Recording” after the microphone has ended

**Location:** [app:288–319][night-screen]. `updateNight()` unconditionally prints `Recording · … snores`. The new interruption warning updates the underlying status, behind the overlay.

**Executed reproduction:** in Chromium, start, choose Darken screen, stop the fake track and dispatch its system-style `ended` event. The controller had an ended-track gap, but visible text remained **“Recording · 0 snores”**. Hit-testing confirmed the night overlay covered the warning. Waking and darkening again still displayed “Recording”, so this is not merely a delayed redraw.

**Impact:** someone checking the bedside clock sees an affirmative recording status while input has stopped. This leaves part of R1’s silent-failure problem in the app’s normal overnight view.

**Proposed fix/acceptance:** derive night-screen text from the same recording/interruption state as the main status, and refresh it on transitions. A stopped input must be visibly distinguishable without leaving night mode. This does not require moving the Darken screen button.

### C3 — Medium: PNG/HTML sharing treats an interrupted night as continuous and mixes duration definitions

**Locations:** [app:638–647][share-data] passes `clockSeconds` as a single `elapsed` value, without gaps or captured duration. [share:197–210][share-card] and [share:489–545][share-html] use that value for duration and short-recording decisions, while percentages and rates come from captured-time statistics.

**Executed reproduction:** feed 30 seconds of synthetic audio into the real recorder, end the fake microphone, advance the fake clock one hour and stop. Six snores were counted; analyzed duration was **29.952 seconds**. JSON correctly recorded a **3,600-second gap**. The HTML said:

> 6 snores in 1 h 0 min, about 721 per hour.

It contained **no interruption warning**. The PNG path also uses wall/gap time to choose the per-hour headline and labels the captured-time percentage “of the night”.

**Impact:** shared outputs can look like complete overnight evidence even when almost all the period was missing. Rates themselves use the approved captured-time denominator; the failure is presentation and inconsistent confidence/duration gating. Passing the normal uninterrupted sharing test does not cover it.

**Regression classification:** this inconsistency accompanies the new gap-aware clock passed into the existing share builders.

**Proposed fix/acceptance:** carry actual start/end, captured time and gaps separately into both builders. State coverage, mark missing intervals and base short-recording warnings on captured time. Keep the approved rate/counting denominator. Compare page, JSON, HTML and PNG for one interrupted night.

### C4 — Medium, before enabling saved nights: the store does not enforce its isolation/privacy contract

**Locations:** [night-store:55–104][store] and [recorder:354–385][night-record].

**Executed reproductions:**

- Finalize a night with `summary.snoreCount = 0`; load it; change the returned nested summary to 999. Loading again returns **999**, although the night is “read only”. A nested configuration in `meta` is shared too.
- Store an accepted event and its clip; upsert that event as rejected. Loading returns **isSnore=false with one retained clip**. The clip eligibility check only runs at append time.
- The completed recorder record is frozen at its root, but changing its nested summary changes `recorder.night.summary`.

**Impact:** a future history editor or consumer can mutate stored/finalized data accidentally. The generic event-update API can leave audio attached to an event it now describes as rejected.

**Scope:** `night-store.js` is not loaded by the current page. The live classifier does not currently revise accepted events into rejected ones; the reclassification case tests the advertised store contract. I did not observe current-user data corruption or a current privacy leak through this unused module.

**Proposed fix/acceptance:** return independent data snapshots; define a typed, explicit persisted schema; make clip/event consistency atomic. Either reject unsupported classification changes or remove ineligible clips in the same operation. Extend contract tests for nested mutation and verdict changes. Clarify whether finished records promise immutability or merely read-only usage.

### C5 — Low: a delayed wake-lock request can acquire a lock after Stop

**Locations:** [recorder:125–144][wake-lock], [recorder:335–340][rec-stop].

**Executed reproduction:** defer the wake-lock request promise, start and immediately stop, then resolve it with a sentinel. Result: recorder **completed**, `wakeLockState = 'on'`, sentinel **release called zero times**.

**Impact:** the page can keep the display awake after recording has ended. Overlapping requests can also overwrite ownership; that second consequence is inferred from the same shared variable, not separately measured here. The underlying async race existed before the refactor.

**Proposed fix/acceptance:** associate requests/sentinels with a recording generation, release stale acquisitions immediately, and ignore release callbacks for obsolete sentinels. Test delayed resolution after Stop and after a subsequent Start.

### C6 — Low: automatic-sensitivity history uses a different clock from exported events after a gap

**Locations:** [detector:534–542][auto-clock] records levels using sample time; [report-format:111–119][level-export] emits that as `offsetSec`, while event offsets include interruptions.

**Executed reproduction:** process 30 seconds, call `resumeAfterGap(3600)`, then process another 30 seconds. The first post-gap sensitivity entry is stamped **30.016 s**; the detector’s event clock at that point is approximately **3630.016 s**. Final event clock is 3660 s.

**Impact:** a consumer aligning shadow thresholds with snores/interruptions will place this threshold change an hour too early. Aggregate counts and the current CLI’s min/median/max threshold summary are unaffected.

**Proposed fix/acceptance:** use the same clock or explicitly name/document separate sample-time and wall-offset fields. Test a known threshold-history point on both sides of a gap. The live pill also compares frame time without the gap offset against event end time with it ([app:373–381][pill]); align that time contract as part of the fix.

## 4. Regression, privacy and data-model assessment

### What the comparisons support

The baseline and current `DEFAULTS` and `SENSITIVITY` objects are identical. I compared **27 combinations**: 16/44.1/48 kHz × seeds 1/2/3 × Normal, Normal+breath and Auto+breath.

- Current versus v1.9.1: event objects and encoded WAV bytes were identical for every ordinary demo combination.
- Current versus `cd25c7a`, immediately before the statistics/WAV split: **events, summaries and WAV bytes were identical in all 27 combinations**.
- The original special rhythm probes now produce the approved changed behavior.
- Full browser demo, export evaluation, current public benchmark and legacy report fixtures agree with the verification document.

This is substantial evidence that the module extraction preserved normal behavior. It does not prove every sound, interruption or browser path equivalent.

### Interruption decisions still needing precision

[stats:109–155][stats-summary] prevents cross-gap confirmation but still joins independently confirmed groups into an episode across a short interruption. In a direct probe, starts **2/6/10 and 30/34/38**, with a gap **15–25**, form **one 37-second episode** with mean interval 7.2 seconds. Whether episodes should split is a **product/statistics decision**: the owner approved no confirmation across gaps, not an explicit episode policy. Mark unobserved spans and obtain that decision before changing episode counts.

[detector:408–412][resume-gap] closes events/resets rhythm but leaves the partial analysis frame and raw ring intact. A probe retained 372 pending samples over a 60-second gap. Thus frame assembly and pre-roll can span a discontinuity even though event/rhythm state is broken. I did not establish a consequential counting error from this during the review. Specify and test this boundary before relying on exact gap-edge clips.

Stop calls `release()` before reading `elapsed`, so clearing `pendingLen` drops the final partial-frame duration ([recorder:313–318][rec-stop]). This is a sub-frame discrepancy, not lost minutes. Decide whether captured time means samples received or complete frames analyzed, and use that definition consistently.

### Privacy and security

Source review found **no automatic audio/report upload, analytics client or network transport for night data**. Browser observation saw an external Google Fonts stylesheet GET with no request body; no audio/report request was observed in that session. This is consistent with local processing, not a claim that the page makes no external requests.

After Stop, the main and both shadow detector scratch buffers were zeroed in the controller probe. Accepted short clips remain by design; false classifications and neighboring sounds remain possible, as the revised wording states. The original core probe’s retained speech after `flush()` alone is not a failed Stop fix: Stop also calls `release()`.

Existing HTML escaping and internal numeric sources protect the current rendering paths; the script-free report tests pass. I found no current externally controlled HTML-injection path. Before importing reports or adding user-provided profile names, validate shapes, finite numeric values and URL types; `fromReport()` is a compatibility reader, not a comprehensive untrusted-input validator. Its round-trip test does not establish that it reconstructs a full finished-night object.

Schema 2 preserves the old export fields, but omits the finished record’s ID, time zone, sample rate and full configuration. Readback also does not reconstruct `end` on events or the `SessionStats` instance. That is adequate for the current evaluator’s subset of needs; it is not yet a durable history interchange model.

## 6. Is this a sound foundation for a larger app?

**Yes, for incremental expansion. More folders are not the immediate blocker. Data ownership, persistence guarantees and separation of platform recording are.**

The pure detector/statistics/WAV modules and shared fixtures are reusable. A controller with explicit states is an improvement over audio lifecycle code inside the page. Keeping a completed night separate fixed a real export failure.

The split is incomplete: app.js still owns live/report/night UI, playback and sharing; recorder.js owns both recording policy and browser audio/wake-lock APIs; the page reads detector/statistics internals through `recorder.session`. These are manageable at the present size, but a native backend or history view should consume stable data interfaces.

A proportionate organization, when those features arrive:

| Area | Suggested responsibility |
| --- | --- |
| `js/core/` | Signal analysis, classification, rhythm and statistics; no DOM/storage |
| `js/session/` | Recording state, gap clock, configuration snapshot, event updates |
| `js/platform/browser/` | Audio graph, microphone and browser lifecycle/wake lock |
| `js/storage/` | Store contract, IndexedDB implementation, migrations, recovery |
| `js/ui/` | Live, night, report and history views |
| `js/reporting/` | JSON/WAV/HTML/PNG output with one explicit time contract |
| `tests/unit/`, `tests/integration/`, `tests/e2e/` | Distinct domain, persistence/lifecycle and browser checks |
| `ios/` | Add when a native recording prototype exists |

Do not create empty folders or rewrite the whole app just to match the table. UMD can remain during incremental work. ES modules, JSDoc/type checking or a framework are separate engineering choices; the current file-URL builds and Node consumers need migration tests if module loading changes.

### On-device nights and a history screen

The store is a **useful sketch**, not a complete recovery design. Before implementing IndexedDB:

1. Resolve C4 and define a plain versioned Night/Event/Clip schema. Preserve IDs, schema/detector versions, configuration, time zone, sample rate, captured time, gaps and completion/recovery status. Keep derived views separate from stored records.
2. Add a durable progress/checkpoint operation. The present API supplies final timing/gaps only at `finalize()`; a crash before Stop must still preserve coverage and the last safely saved point.
3. Define how confirmation updates reach storage. [stats:69–77][confirmation] mutates earlier events when a neighbor arrives, but [recorder:260–265][rec-event] notifies only the newly delivered event. Naively appending only callback events would miss previous-event updates. Emit changed-event batches or deterministically recompute with persisted gap data.
4. Make event/clip/checkpoint writes atomic where necessary; bound the write queue and RAM; handle quota errors, partial writes, migration failures and deletion of clip data. Never persist raw continuous room audio as an intermediate shortcut.
5. Recover after a real reload/process termination, then build the history screen on loaded records. Test loading old schemas, an unfinished night, export/playback after reload, and deleting one night without affecting another.

IndexedDB is an appropriate browser implementation behind the interface. Browser storage is best-effort unless persistence is granted and remains user-deletable; expose failure and export options. See [storage persistence documentation][storage-docs].

The 1,500-clip limit is still roughly **106 MB of PCM** at 8 kHz/16-bit with 4.4 seconds per clip, before export copies and other data. This is a sizing estimate, not a measured crash. History should load clips lazily and enforce a byte/retention budget.

### Native iPhone recording

Replacing the browser-facing recording layer is a reasonable direction, but injecting fake AudioContext objects is a testing seam, not yet a native audio-source interface.

Define the platform contract around timestamped mono PCM, sample rate, input/route/interruption events, start/stop outcomes and ownership of recovery. Demonstrate that **capture, detection and incremental storage continue while the UI is suspended or the screen is locked**. A native microphone feeding JavaScript in a suspended web view does not by itself establish that guarantee; this is an architectural inference to validate in a prototype.

Apple documents audio-session configuration, background audio mode and interruption handling: [record category][apple-record], [audio interruptions][apple-interruptions]. Prototype a locked-phone night, calls/Siri, route changes, restart recovery and battery/memory behavior before committing to the complete native conversion. Reuse the deterministic fixtures to check any port of the detection engine. Persist only accepted short clips.

### Users and accounts

For local profiles, add profile ownership to the local data model only when needed. Cloud accounts/sync require server-enforced ownership and a separate decision about whether summaries, clips or both leave the device. They would change today’s privacy promise. They are not prerequisites for a useful local history screen.

## 7. What to do first

1. **Stabilize interruptions and their presentation:** C1–C3, with real iPhone checks and explicit coverage in every export.
2. **Complete the data/storage contract before connecting persistence:** C4, progress checkpoints and confirmation updates.
3. **Fix the narrow lifecycle/clock issues:** C5–C6; settle gap-edge and episode semantics with the owner where behavior is a choice.
4. **Implement recoverable local nights, then history.** Keep accounts deferred.
5. **Prototype native background recording early**, before promising dependable screen-off iPhone operation.

The existing functionality merits preservation. None of the evidence calls for retuning thresholds or promoting the background variants. Continue the owner’s planned real-night comparison with explicit coverage information.

## Appendix B — Minimal controller and storage reproductions

Save this script **outside the repository**, then run `node <script.cjs> /absolute/path/to/Snore`. It loads the exact checkpoint’s existing fake-browser helper without editing it. The simulated clock does not establish physical-phone behavior.

~~~javascript
const fs = require('node:fs');
const path = require('node:path');
const vm = require('node:vm');
const { createRequire } = require('node:module');
const repo = process.argv[2];
const get = name => require(path.join(repo, name));
const { createRecorder } = get('js/recorder.js');
const { createMemoryStore } = get('js/night-store.js');
const Core = get('js/detector.js');
const Synth = get('js/synth.js');
const Share = get('js/share.js');
const Report = get('js/report-format.js');

const helperPath = path.join(repo, 'tests/recorder.test.js');
const box = { require: createRequire(helperPath), module: { exports: {} } };
vm.runInNewContext(
  fs.readFileSync(helperPath, 'utf8').split("test('a night goes")[0]
    + '\nmodule.exports = fakeBrowser;',
  box
);
const fake = box.module.exports;

(async () => {
  for (const state of ['suspended', 'interrupted']) {
    const b = fake();
    let resumes = 0;
    b.env.AudioContext.prototype.resume = async () => { resumes++; };
    const rec = createRecorder({ env: b.env });
    await rec.start();
    rec.session.ctx.state = state;
    rec.session.ctx.onstatechange();
    for (let i = 0; i < 4; i++) { b.advance(1000); b.tick(); }
    b.env.document.dispatch('visibilitychange');
    console.log('C1', state, resumes);
    rec.stop();
  }

  const b = fake();
  let finishRequest, releases = 0;
  b.env.navigator.wakeLock = {
    request: () => new Promise(r => { finishRequest = r; })
  };
  const rec = createRecorder({ env: b.env });
  await rec.start();
  rec.stop();
  finishRequest({
    addEventListener() {},
    async release() { releases++; }
  });
  await Promise.resolve();
  console.log('C5', rec.state, rec.wakeLockState, releases);

  const audio = fake();
  const r = createRecorder({ env: audio.env, version: 'review' });
  await r.start();
  audio.feed(Synth.demoScenario(16000).samples.subarray(0, 30 * 16000));
  audio.track.readyState = 'ended';
  audio.track.dispatch('ended');
  audio.advance(3600000);
  const night = r.stop();
  const html = Share.buildReportHtml({
    startWall: night.startWall, elapsed: night.clockSeconds,
    snores: night.stats.confirmed, summary: night.summary,
    version: 'review', sensitivity: night.sensitivity,
    sourceLabel: 'Synthetic review', reasons: Core.REASONS,
    samples: { loud: [], random: [] }
  });
  console.log('C3', Report.toReport(night).interruptions,
    html.match(/<p class="verdict">([^<]*)/)[1]);

  const store = createMemoryStore();
  const id = await store.create({ startWall: 0 });
  await store.appendEvents(id, [{ id: 1, start: 2, isSnore: true }]);
  await store.appendClip(id, 1, new Int16Array([9, -9]), 8000);
  await store.appendEvents(id, [{ id: 1, start: 2, isSnore: false }]);
  await store.finalize(id, { summary: { snoreCount: 0 } });
  const loaded = await store.load(id);
  loaded.record.summary.snoreCount = 999;
  const again = await store.load(id);
  console.log('C4', again.events[0].isSnore,
    again.clips.size, again.record.summary.snoreCount);

  const d = new Core.SnoreDetector(16000, { sensitivity: 'auto' });
  const quiet = Synth.compose(16000, 30, [], 4).samples;
  d.process(quiet);
  const before = d.levels.length;
  d.resumeAfterGap(3600);
  d.process(quiet);
  console.log('C6', d.clock, d.levels[before].t);
})().catch(e => { console.error(e); process.exitCode = 1; });
~~~

Expected essential output: C1 **6 vs 0**; C5 **completed/on/0**; C3 **one-hour gap absent from HTML verdict**; C4 **false/1/999**; C6 **3660 / approximately 30.016**.
